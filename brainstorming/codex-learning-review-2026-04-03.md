## PPT 核心观点摘要

这份 PPT 的核心方法论可以概括为三句话：

1. 聚焦比“一次做完所有事”更重要。
2. 一步一角色，如果一步里混了多个角色，就应该拆开。
3. 让 AI 先拆，你来审；合理不等于合适。

PPT 强调，顶级 AI 的变强并不是因为“单次思考更全能”，而是因为它们把任务切成多个专职环节，每一步只处理一个明确目标，并且用机制约束每个环节的权限和边界。

这套方法对我们当前的动效提示词 skill 很有参考价值，因为 `slots-fx-prompt` 已经具备“分步确认”的骨架，但还没有完全做到“按角色拆解”和“检查执行分离”。

## 对当前 slots-fx-prompt skill 的观察

当前 skill 的优点：

- 已经具备强制分步确认机制。
- 已经区分了工具选择、模式选择、场景选择、方案预览、最终生成。
- 已经有规则库、风格库、合规过滤等支撑文件。

当前 skill 的主要问题不是“没拆步骤”，而是“步骤还偏流程化，角色边界还不够硬”。

换句话说，现在更像是：

- 一个大 prompt 按顺序做很多事。

而不是：

- 多个清晰角色各自只做一件事，再把结果交给下一步。

## 面向当前 skill 的优化建议

### 1. 从“流程步骤”升级为“角色分工”

建议把整个 skill 明确拆成以下角色：

- 路由器 Router：只负责判断是否触发、是否属于 slots 游戏场景、应该走 Scene A/B/C 哪条线。
- 配置官 Configurator：只负责补齐生成所需参数，不负责写方案。
- 动效策划 Motion Planner：只负责输出 2-3 个差异明确的候选方案，不生成最终提示词。
- 提示词工程师 Prompt Writer：只负责把已确认方案翻译成 Vidu Q2 / Seedance 2.0 的最终提示词。
- 质检官 Verifier：只负责检查格式、禁用项、合规项、场景约束，不负责改写内容。

这样做的好处是：

- 每一步只承担一种认知任务。
- 更容易发现错误出在哪一层。
- 后续 Claude 如果要继续优化，也更容易局部替换而不是整体重写。

### 2. 把 STEP 4 预览阶段变成真正的“决策闸门”

当前 STEP 4 已经很关键，但还可以更强：

- 在用户没有选定方案前，禁止生成最终提示词。
- 预览阶段只输出“动作方案”，不输出最终文案句式。
- 每个候选方案必须显式带上：
  - 动作核心
  - 节奏类型
  - 视觉重心
  - 是否满足排除项

目标是把“创意决策”与“提示词写作”彻底拆开。

### 3. 从固定追问改成“状态补全”

当前 skill 的追问顺序很完整，但偏表单式。

建议维护一个内部配置状态对象，例如：

```text
tool
mode
intent
scene
subject_type
motion_state
material_type
style_profile
constraints
selected_scheme
```

然后每轮只补问“当前最影响输出质量的一项缺失信息”，而不是机械地走完整固定顺序。

这样能减少用户疲劳，也更符合“每一步只做一件事”的原则。

### 4. 把规则库与生成器拆开

当前 `motion-rules.md` 同时承担了：

- 动效允许/禁止规则
- 动作设计参考
- 生成时的语义约束

建议拆成两层：

- Rule Layer：纯规则，不负责措辞。
- Motion Skeleton Layer：根据主体 + 状态 + 强度，产出中间动作骨架。

中间骨架建议长这样：

```text
主体：虎头图标
状态：Win
动作骨架：低头蓄力 -> 抬头咆哮 -> 眼部爆亮 -> 鬃毛外炸 -> 光晕扩散 -> 粒子收束
限制：无镜头运动 / 无大位移 / 无朝向变化
循环要求：否
```

最后再由 Prompt Writer 把骨架转成目标工具文案。

这样会比“边查规则边写最终提示词”稳定得多。

### 5. 给每一步增加“完成标准”

当前文档写了步骤，但“什么算完成”还不够硬。

建议每一步都补一个完成标准，例如：

- STEP 1 完成：目标工具、生成模式、意图已确认。
- STEP 2 完成：场景已唯一确定为 Scene A/B/C。
- STEP 3 完成：主体类型、状态类型、素材类型已确认，且素材可用。
- STEP 4 完成：用户已选择 1 个预览方案。
- STEP 5 完成：最终提示词通过格式检查、合规检查、约束检查。

这会明显提升后续 AI 的自检能力和人工 review 效率。

### 6. 引入“验证者只检查不改写”

这是 PPT 里最值得直接落地的一点。

建议把验证逻辑单独抽出来，只做以下检查：

- Idle 是否明确无缝循环
- 是否出现镜头运动或不允许的位移
- 是否出现模糊动作描述
- 是否与主体专项动作规则冲突
- 是否满足 Vidu / Seedance 各自格式要求
- 是否触发合规过滤规则

如果检查失败，不要在验证层直接偷偷改写，而是返回：

- 哪条不满足
- 应该回退到哪一层重生成

例如：

```text
失败原因：中奖动作缺少明确部位和因果链
回退层级：Motion Skeleton Layer
建议补齐：头部动作、眼部变化、能量释放路径
```

这样才能真正做到“检查与执行分离”。

## 建议 Claude 后续重点分析的方向

如果后续让 Claude 继续分析当前 skill，建议重点看下面 5 个问题：

1. 现有 skill 能否拆成多个更清晰的角色模块，而不是单一长流程？
2. 现有 references 是否混合了承担“规则、决策、生成、校验”四类职责？
3. 哪些步骤必须用户确认，哪些步骤可以默认推断，边界是否足够清晰？
4. 是否应该引入中间产物，例如 motion skeleton，而不是直接生成最终提示词？
5. 最终输出前是否需要一个只读 verifier 层，专门负责格式与约束检查？

## 一句话结论

当前 `slots-fx-prompt` 的问题，不是“没有拆步骤”，而是“还没有把步骤彻底角色化、状态化、可验收化”。

下一阶段优化方向应该不是继续加规则，而是：

把“流程”升级为“角色协作”；
把“直接生成”升级为“中间骨架 -> 最终文案”；
把“生成顺带检查”升级为“执行与验证分离”。
